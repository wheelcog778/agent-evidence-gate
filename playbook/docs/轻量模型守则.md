# 轻量模型守则：12 条让弱模型也能交付的结构

前提：**强弱模型在"开放式规划"上差距最大，在"受约束的执行"上差距最小。**
这份守则的全部目的，是把任务从前者挪到后者。

每条写清：弱模型会怎么错 / 结构上怎么补。

---

## 1. 一张卡只做一件事

**会怎么错**：塞给它三件事，它做完第一件就忘了第三件，或者把两件事的产物混在一个文件里。
**怎么补**：一个任务一个 `work/` 目录、一个产物、一个验收判据。要做三件事就开三张卡，用 `parent` 串起来。

## 2. 输入给路径，不给全文

**会怎么错**：prompt 里贴 8KB 材料，它读到一半开始编，或者照着前几段套模板。
**怎么补**：只给它文件路径和"读哪几节"的指令。它自己读，读多少由它决定，但你的上下文不被污染。

## 3. 输出形状写死

**会怎么错**：让它"写份报告"，它给你散文；下次再要，格式又变了，下游解析不了。
**怎么补**：模板给死。比如 `report.md` 必须有 `## 结论` / `## 证据` / `## 缺口` 三节，缺一节判失败。弱模型很擅长填模板，很不擅长发明结构。

## 4. 判据写成可执行的命令

**会怎么错**：你说"数据要准确"，它给你一个看起来对的数字。
**怎么补**：判据是命令，不是形容词。
```bash
# 不是"数字要准"，而是：
python -c "import sys,re; ..."  # 输出行数
```
跑出来的值对不上就判失败，不辩论。

## 5. 一次只做一步，不要"顺便"

**会怎么错**：让它"整理数据并顺便分析"，它把分析当成了整理，交上来一段感想。
**怎么补**：`整理` 一张卡、`分析` 一张卡。第二张卡的输入是第一张卡的产物路径。

## 6. 不确定的部分必须显式写出来

**会怎么错**：没读到的部分它会编。弱模型编得比强模型更自信，因为它更少自我怀疑。
**怎么补**：模板里留一节 `## 缺口`，写"我没看到什么、不能确定什么"。这一节为空反而要警惕——说明它在装懂。

## 7. 给一个输入输出样例

**会怎么错**：你描述十遍格式，它还是猜。
**怎么补**：给一对真实样例（输入是什么、输出长什么样）。一个样例胜过五句描述，弱模型尤其如此。

## 8. 单步推理不超过 3 跳

**会怎么错**：让它"读 A、比对 B、算出 C、判断 D"，它会在第 3 跳丢约束。
**怎么补**：拆成三张卡，每张卡只跨一跳。中间结果落盘，下一张卡从磁盘读，不从上下文读。

## 9. 失败必须带原因，不许静默

**会怎么错**：跑挂了不报错，返回一个空结果，看起来像"没找到"。
**怎么补**：`manifest` 里 `verdict` 非空是硬门；`exit_code != 0` 直接判失败。空结果和没跑必须能区分开。

## 10. 预算硬上限，超了就丢

**会怎么错**：上下文越滚越大，最后几轮它开始重复前面的话。
**怎么补**：四槽预算（任务/上游/岗位/规则），每槽有字节上限，超了整槽丢弃并记录。弱模型在长上下文里退化得比强模型快得多。

## 11. 不让它管调度

**会怎么错**：让它"自己决定下一步做什么"，它会给自己派一堆无关的活，或者原地打转。
**怎么补**：谁拿任务、什么时候截止、递归多深，全部由程序定。模型只回答"这张卡怎么做"和"做完了没有"。

## 12. 两段式核验

**会怎么错**：让同一个模型自检，它永远说自己对。
**怎么补**：
- 第一段：有文件/命令权限的 agent 做**实测**（重算 hash、重跑命令）
- 第二段：没有工具的 agent 做**文本一致性**审查（口径自洽吗、数字有出处吗）

两段结论必须分开写：`实测：PASS` / `文本一致性：PASS`。合成一个"PASS"就是在糊弄自己。

---

## 一句话总结

**弱模型不是不能干活，是不能干"没有验收标准的活"。**
你把判据写死、把任务切小、把状态放磁盘，它就只剩"照着做"这一件事——这件事它做得不差。

反过来，一个没有判据的任务，强模型也会给你一份看着像样、实际不可用的东西。
