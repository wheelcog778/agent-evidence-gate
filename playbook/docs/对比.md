# 和别的项目比，差在哪

选型时最有用的一页。**结论先说：它不替代任何框架，它补的是框架都不做的那一块。**

---

## 一句话对比

| 项目 | 解决什么 | 不解决什么 |
|---|---|---|
| **CrewAI / AutoGen / MetaGPT** | 几个 LLM 怎么轮流说话、怎么扮演角色 | 幂等、租约、审批、证据、沙箱生命周期 |
| **LangGraph** | 有状态图 + checkpoint，工程扎实 | 同样：你得自己写队列、审批、证据 |
| **OpenHands** | 单个 agent 在沙箱里干活（最强执行面） | 多任务排队、谁来做、做完了算不算完 |
| **OMA (open-multi-agent)** | 自托管 runtime + 审批门 + 离线审计 | 上下文预算、终态保护、命令级证据 |
| **Aegis** | "evidence-verified" 的 agent 编码流程 | 队列、租约、审批、崩溃回收 |
| **agent-bus（本项目）** | 任务该谁做、能不能信、崩了怎么办 | 它**不会**让模型变聪明，也不管多机 |

## 市场分布（2026-11 实测）

搜索 `agent task queue sqlite` 的结果：

| 项目 | Stars |
|---|---|
| alanxurox/mission-control（Bash+SQLite） | 35 |
| vbgate/opencode-supertask | 13 |
| aqm-framework/aqm | 13 |
| cgeene/commandcenter | 11 |
| 其余 | 3–4 |

搜索 `agent evidence verification` 的结果：

| 项目 | Stars |
|---|---|
| teaql/teaql-agent-kit | 2,818 |
| GanyuanRan/Aegis（evidence-verified） | 1,422 |
| VibeTensor/attestix | 685 |

**读法**：
- "任务队列"这个形态天花板是两位数——大家不觉得这是个问题。
- "我凭什么信 agent 的产出"能到四位数——大家真的被坑过。

所以这个包的定位应该是**证据门**，不是任务队列。

## 和 OMA 的具体差异

OMA（7k stars）是最接近的：自托管、有审批门、能离线审计。

| 维度 | OMA | agent-bus |
|---|---|---|
| 语言 | TypeScript | Python（标准库，零依赖） |
| 审批门 | 有 | 有（四类：外发/花钱/删除/改权限） |
| 租约与崩溃回收 | 有 | 有（attempts 上限 → dead） |
| 上下文预算 | 无（按需拼 prompt） | 有（四槽字节硬上限 + 节省量化） |
| 命令级证据 | 无（审计事件） | 有（cmd + exit_code + stdout_sha256 + produced_by） |
| 终态保护 | — | 有（终态不可复活，专门写了测试） |
| 跨机 | 支持 | 不支持（SQLite 单机） |
| 生态/集成 | 较多 | 无 |

**如果 OMA 已经满足，不要用这个。** 这个的价值在"上下文预算 + 命令级证据"两点，其余更弱。

---

## 和 CrewAI 的具体差异

CrewAI 的书里没有"任务失败了怎么办"这一章。

| 场景 | CrewAI | agent-bus |
|---|---|---|
| 同一个任务跑了两遍 | 会 | 不会（nonce 幂等） |
| worker 崩了 | 卡住 | 租约过期回收，重试有上限 |
| agent 说"做完了" | 你信 | 证据门：文件+hash+命令+退出码 |
| 要发外部消息 | 直接发 | 拦下来等人批 |
| 上下文 | 全量滚 | 四槽预算，超了丢 |

CrewAI 适合：一次性的、几十分钟的、你在旁边看着的任务。
agent-bus 适合：要跑很多次、你可能不在、错了要能查的任务。

---

## 什么时候不要用这个

- 你的任务一次就跑完，不需要排队 → 直接调 API 更快
- 你会盯着每一步 → 不需要证据门，你自己就是证据
- 你要多机/高并发 → SQLite 不合适，换 Postgres 或 OMA
- 你需要"agent 自己会规划" → 这个包明确不提供，它只保证执行和验收

---

## 判断标准

选型时问自己三个问题：

1. **这个任务会跑第二遍吗？** 会 → 需要幂等，别用裸 API。
2. **出错时我能查清是哪一步吗？** 不能 → 需要事件日志和证据门。
3. **有我之外的人会看这个产出吗？** 有 → 需要可复算的证据，不是"agent 说完成"。

三个都是"否"，别用任何框架，写个脚本就行。
