# 任务卡模板

复制这段，填完再提交。**空着的字段就是这次交付的漏洞。**

```json
{
  "title": "一句话说清这张卡做什么（动词开头）",
  "agent": "researcher",
  "parent": null,
  "priority": 1,
  "deadline_seconds": 1800,

  "payload": {
    "target": "C:/绝对路径/要读的文件.md",
    "ask": "上游要什么，用原话，不要转述",
    "inputs": ["C:/其他输入文件"],
    "do_not_read": ["不要读的目录，防止它乱翻"]
  },

  "accept": {
    "artifacts": ["report.md"],
    "required_sections": ["## 结论", "## 证据", "## 缺口"],
    "must_run": ["至少一条命令，输出要与结论里的数字对应"],
    "verdict_rule": "结论必须有出处；没有出处的数字判 FAIL"
  }
}
```

## 填写要点

**title**：动词开头。"统计"、"核验"、"抽取"、"改写"。不要写"关于 X 的研究"这类没有动作的词。

**agent**：一个角色，不是"任何人"。角色决定它能看到什么岗位说明。

**deadline_seconds**：必须填。没有截止时间的任务会一直挂着烧钱。

**payload.target**：给路径，不要贴全文。它自己读，读多少它决定。

**payload.ask**：写上游原话。这是交接表里的"上游要什么（原话）"那一列，转述会丢信息。

**payload.do_not_read**：写清楚不许读什么。弱模型很容易"顺便"去翻别的目录，一翻就超预算。

**accept.required_sections**：章节名写死，缺一节判失败。这是最便宜的自动化验收。

**accept.must_run**：要求它至少跑一条命令，且结论里的数字要和输出对得上。

# 岗位说明模板

放到 `profiles/<agent>.md`，会被塞进这个 agent 每张卡的上下文（有字节上限，别写长）。

```markdown
# 岗位：<名字>

## 你负责
一句话。具体到产出什么。

## 你不负责
- 不做最终判断（那是 verifier 的事）
- 不读与本卡无关的历史
- 不修改输入材料

## 交付契约
必须在 work/ 下写两个文件：
1. `<产物>.md` —— 必须含 `## 结论` / `## 证据` / `## 缺口`
2. `manifest.json` —— artifacts 带 path + sha256 + produced_by；
   commands 每条带 cmd / exit_code / stdout_path / stdout_sha256；
   output_summary 一句话；verdict 非空

## 判断标准
数字要能复算；引用要给文件路径；没读到的写进「缺口」，不许猜。
```

## 写岗位说明的三条

1. **越短越好**。它进的是 agent 的上下文，不是文档站。超过 1KB 就砍。
2. **写"不负责什么"比写"负责什么"重要**。弱模型的越界主要来自职责边界模糊。
3. **不要写"要有责任心"这种话**。写可执行的要求：必须写哪三节、必须给路径、不许猜。
